One task, end to end

  1. Step 1 of 5

    An event arrives

    A new issue in Linear or a review on GitHub fires a webhook. hermesQ catches it on a Cloudflare Worker and the agents pull it, so nothing in my network is exposed.

  2. Step 2 of 5

    The coordinator decides what runs first

    Every task sits in a dependency graph. The coordinator picks the next node that is ready and hands it to exactly one agent.

  3. Step 3 of 5

    Agents work in parallel, isolated

    Each coding agent gets its own git worktree and loads only the skills it needs, which keeps context small and tokens cheap.

  4. Step 4 of 5

    QA approves or sends it back

    A QA agent reviews every change. Rejected work returns to the coder with the reason attached, until it passes.

  5. Step 5 of 5

    A human holds the keys

    Secrets are released per request with Touch ID and the release waits for my approval. Then CI/CD ships it.

Research

Deterministic multi-agent orchestration, at Solidareasy since 2025.

Orchestration on Hermes

Twelve specialized AI agents on self-hosted machines in a private Tailscale network. A task graph decides what runs first; a deterministic Kanban engine routes one task per agent.

hermesQ (open source)

The communication bridge: a Cloudflare Worker that receives GitHub, Linear, Stripe and Slack webhooks and delivers them to the agents over outbound-only long-poll.

Zero-trust secrets

Agents never hold API keys. They reach services through OIDC, and each secret is released on request with Touch ID.
